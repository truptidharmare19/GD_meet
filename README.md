# GD Meet

A Python/FastAPI group-discussion prototype with shareable meeting links, live audio/video, browser speech captions, and a Gemini-generated report.

## Run locally

1. Make a virtual environment with Python 3.13 or 3.14 and install dependencies:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   ```

2. Set up your local Gemini key. `.env` is ignored by Git:

   ```powershell
   Copy-Item .env.example .env
   ```

   Add your key to `GEMINI_API_KEY` in `.env`. Never paste the key into source code, commit it, or share it in chat.

3. In the first terminal, start the app and leave it running:

   ```powershell
   python -m uvicorn app.main:app --reload
   ```

4. In a second terminal, start ngrok:

   ```powershell
   ngrok http 8000
   ```

   Wait for ngrok to show a `Forwarding` line with a public `https://...` address. Keep both terminals running while people join.

5. Open that public HTTPS address, enter your name, and create a meeting. Copy the participant link shown in the meeting and send it to participants. They must use the link from that same public address, not `localhost` or `127.0.0.1`. Once at least two people are connected, the moderator welcomes the group and asks whether everyone has arrived. Any participant can say **“yes”** to have the moderator announce the topic. The host selects **End meeting** to hear the closing message and receive the report.

   If the public address works on one network but not another, that network may block ngrok. Test from mobile data as well as Wi-Fi. For a stable link that does not depend on your laptop or ngrok staying online, deploy the app using the steps below.

## Deploy for internet participants

The local address (`127.0.0.1`) points back to the computer opening the link. To let participants join over the internet, deploy the app and share its public HTTPS link.

This repository includes a Render Blueprint in `render.yaml`:

1. Push the project to GitHub. Keep `.env` out of Git; it is ignored.
2. In Render, choose **New → Blueprint**, connect the GitHub repository, and apply the `render.yaml` configuration.
3. Enter `GEMINI_API_KEY` in Render's environment-variable prompt or service settings. Do not commit or paste the key into the repository.
4. When deployment finishes, open the Render `onrender.com` HTTPS URL. Create the meeting there and share the participant link generated by that page.

The HTTPS deployment allows browser camera, microphone, and screen-sharing access. Use **Share screen** in the meeting controls to present a screen or window; browser support and permissions apply. The meeting UI does not display the transcript. When the host ends the meeting, the server appends the transcript and generated discussion report card to `transcript.txt` in the project folder; this local file is ignored by Git. The report includes participant scores, transcript evidence, strengths, and improvement suggestions. Captions are also sent to Gemini for feedback as described above.

WebRTC audio/video may need a TURN relay when participant networks block direct peer-to-peer connections; ngrok forwards the web app but does not relay call media. On phones, tap **Enable audio** once joined if the browser blocks autoplay; check device media volume and that the microphone button says **Mute mic** (meaning the mic is on). The app reports when audio packets arrive or a TURN relay may be needed. It supports TURN REST credentials: set `TURN_URLS` to a comma-separated list of TURN URLs and `TURN_SHARED_SECRET` to the shared secret configured on a TURN server with REST authentication enabled. The server issues one-hour credentials to participants. Keep the shared secret private and configure the same values in the local `.env` or Render environment settings. Without these settings, the app uses STUN only and some networks may not connect. Rooms are stored in memory, so keep one running instance and do not restart or redeploy while a meeting is in progress.

## Prototype limitations

- Rooms and transcripts are stored in server memory and disappear when the server restarts.
- Audio/video uses peer-to-peer WebRTC mesh. This is intended for small practice groups, not large meetings; a production version should use a media server/SFU and a configured TURN service.
- Browser speech recognition runs separately for each participant and contributes final captions to the room transcript. The browser provider may process audio to provide recognition. Captions depend on browser support, language settings, network, and microphone quality. Chrome/Edge are recommended; this is not guaranteed to be a complete or verbatim recording.
- Meeting transcripts are appended to one local `transcript.txt` file after the host ends each meeting. On hosted services such as Render, local files may be temporary and are not a substitute for persistent storage.
- Browsers require HTTPS for camera/microphone access outside `localhost`. A server running on your own computer is not automatically reachable by participants on the internet; public access requires deployment.
- The transcript is sent to Google Gemini when the host ends the meeting. Participants should avoid sensitive personal information. Gemini feedback and scores are practice guidance, not a validated assessment.
